01The problem

Salesforce is where enterprise data lives. It is also where AI can't fully run.

Building custom AI agents that operate inside Salesforce today forces teams into three bad options.

Option A — Native Agentforce

Salesforce's own AI product is locked to a single model family, extends only via Prompt Builder, and consumes Einstein credits at rates that make heavy usage prohibitive. Customers who already pay for Anthropic or OpenAI API keys can't reuse them.

Option B — Roll your own in Apex

The Apex runtime cannot host a long-lived LLM streaming connection, cannot exceed a 120-second callout timeout, cannot run the Model Context Protocol as a client, and enforces heap limits that break on medium-sized vision inputs. Every serious AI agent built directly in Apex hits a wall.

Option C — Off-platform tools (Zapier, n8n)

These work but sit outside the Salesforce security model. Data access is brittle, admin adoption is low, and enterprises reject them at security review.

The gap Synapse fills
Non-technical Salesforce admins want to build production AI agents — not just prompts. They want vision, tool use, MCP integrations, multi-model choice, and a chat surface that ships inside the org, without writing a line of Node.js or Apex boilerplate.

03The solution

A visual builder inside Salesforce, a chat surface anywhere in the org, a compute layer that carries the load — all speaking one protocol: MCP.

Three surfaces

  • The Canvas — a drag-and-drop LWC where admins wire AI nodes, connector nodes (Salesforce CRM, Slack, custom MCP servers), tool catalog nodes, and system-prompt nodes into working agents. Configuration is stored in AgentDefinition__c + AgentNode__c — no code, no metadata deploys.
  • The Chat Panel — a rich LWC that drops into record pages, utility bars, or standalone tabs. Markdown rendering, table formatting, file uploads (images / PDFs / text), voice input, typing indicator. Multi-turn sessions persist in ChatSession__c.
  • The Node Companion — a TypeScript/Express server that runs the LLM calls, brokers MCP, streams from vision APIs, and manages per-org OAuth. Customers point their org at our hosted instance or self-host.

Model-agnostic by design

The same agent definition runs on any supported engine. Change the AI node's nodeSubType from claude to gpt4 and the workflow, tools, and prompts move with it. No vendor lock-in for the customer or for us.

Key architectural bet
Every LLM provider is racing to natively speak Model Context Protocol. We standardized on MCP as the tool interface a year before it became table stakes. Our standalone Salesforce MCP server is reusable across Claude.ai's native connector, ChatGPT's custom MCP, and any future MCP-aware client — one server, every AI surface.

04Architecture

Three tiers, one protocol, zero SF-API-limit cost on the hot path.

Solid teal = MCP protocol · solid orange = LLM API calls · dashed = attachment stream to MCP

The data flow of one chat turn

  1. User types in the chat panel LWC → optimistic message appears immediately.
  2. LWC invokes AgentChatController.sendTurn with the session ID, text, and any attached ContentDocument+ContentVersion IDs.
  3. Apex fetches session + history (SOQL), builds the payload, and POSTs to the Node server. Zero DML before the callout.
  4. Node validates the session, reads the org's Salesforce OAuth tokens from the install cache (30s RAM), pulls the agent definition from the agent cache (60s RAM).
  5. The chat engine dispatches to the right LLM adapter based on the AI node's sub-type.
  6. The adapter opens a Managed MCP connection to Anthropic/OpenAI, which itself talks to our standalone SF MCP server on Render.
  7. Tool calls (SOQL, record CRUD) execute against the customer's org using their own OAuth token.
  8. Response comes back → Node returns to Apex → Apex persists user + tool + assistant messages in a single DML burst → LWC receives and renders.

05Technical innovations

Where we made non-obvious choices that pay off in latency, cost, or maintainability.

Managed MCP as the tool layer

Rather than implementing an MCP client in Node, we hand the MCP server URL directly to Anthropic and OpenAI's Managed MCP feature. They run the client. This eliminates ~800 lines of protocol code, cuts our latency by removing a hop, and means Claude.ai's native connector and ChatGPT's custom MCP can also talk to the same server — one deployment, three surfaces.

Shepherd URL for attachments

Salesforce Files can be downloaded either through /services/data/ (which counts against the org's 24-hour REST API limit) or through the /sfc/servlet.shepherd/ endpoint (which does not). We use Shepherd as primary with REST as fallback. On file-heavy orgs this is the difference between hitting the quota by 2pm and never hitting it.

Two-layer request cache

Every chat turn used to hit SQLite for the install record and Salesforce twice for the agent definition. We now serve both from RAM with pending-promise dedup: 20 concurrent turns for the same org and agent do one DB read and one SF read, not 40. 60-second TTL keeps admin edits fresh.

Callout-first Apex pattern

Apex forbids DML before an HTTP callout. Our sendTurn does all SELECTs and the callout up front; only after the callout returns (success or failure) do we INSERT the user message + assistant reply — so the transaction commits atomically and never fails with the dreaded "uncommitted work pending" error.

Ephemeral optimistic UI + persistent history

The LWC shows the user's message the instant they hit send, then replaces it with the server-persisted row when the callout returns. If the LLM call fails, we still persist the user's message and a "⚠" assistant bubble — the chat never loses input, matching Slack / WhatsApp behavior.

10Risks & open questions

Honest inventory of what could go sideways and where a decision still needs a shipping stakeholder.

Known risks
  • Anthropic Managed MCP is still beta — the schema shifted twice during our build. We shim behind a stable interface, but a breaking change could stall a release.
  • Render free tier cold-starts (~15-30 s) will fail enterprise SLAs. Paid tier required before GA.
  • SQLite install store won't scale past a single Node instance. Postgres migration must precede multi-instance.
  • Salesforce Shepherd URL for file downloads isn't officially "REST API" — security reviewers may ask. Documented mitigation ready.
  • OpenAI's MCP tool schema changed during our build — could change again pre-GA.
Open decisions
  • Pricing model — per seat, per turn, per agent, or hybrid?
  • Self-hosted Node offer — do we ship a Docker image on day one, or only at Enterprise?
  • Do we build our own eval harness or integrate an existing one (Braintrust, LangSmith)?
  • Auto-title feature — trigger at turn 3 or wait for real substance?
  • Which vector store for RAG — Postgres pgvector (self-contained) or Pinecone (managed but +dependency)?
